# 设计语言：一层玻璃，一张纸

> 这不是参数表，是一组判断。参数会过时，判断不会。
>
> 动手前先答四句话：它是**页面**还是**浮层**？需要**几层**？层之间用**什么手段**分？
> **主动性**放在哪？
>
> 答不上来，说明还没想清楚，先别写 CSS。

---

## 1. 一句话定义

> 页面是一扇玻璃窗，窗内不再有物件浮起来；浮层是一张白纸，纸上靠距离分层。

|        | 页面                         | 浮层（弹窗、下拉、提示）                   |
| ------ | ---------------------------- | ------------------------------------------ |
| 外壳   | 玻璃，透出壁纸               | 玻璃或实白                                 |
| 内部   | 平铺，只有发丝线             | 一张实白纸                                 |
| 为什么 | 页面**就是**这个 app 的样子  | 浮层是一次性工具，背景必须退出画面         |
| 反面   | 整片实白：像别的 app 嵌进来  | 整片玻璃：壁纸花纹变成内容                 |

判断只问一句：**这层表面需不需要露出它所覆盖的背景？** 页面需要，浮层不需要。

风格不是一堆好看的局部拼出来的，是每条决策都能追到一个理由。做不到，单看每个局部都不丑，
合起来就是不和谐——因为它们是不同理由的产物。

## 2. 空间模型：先归位，再谈样式

```
L0  壁纸   彩色，有花纹，是"远"
L1  窗     玻璃，半透明，全站唯一允许透射的一层
L2  表面   窗内的承载面：浮层是白纸，页面就是窗自己的上表面
L3  物件   控件。唯一允许"凹进去"的东西
```

- **从 L0 到 L3，最多穿过一层半透明。** 硬约束。
- **L1 只出现一次。** 窗里不能再开窗。
- **页面没有 L2。** 页面里平铺是默认状态，靠留白和发丝线分组。加一张卡片，
  就是给自己造了一个 L2，然后被迫再为它找材质差——这是"越改越臃肿"的起点。
- **浮层有且只有一张 L2。** 纸上可以有任意多层 L3，但全部不透明。

半透明让背景继续参与画面。一层是"衬底"，两层以上背景就变成了"内容"。
臃肿感的物理来源不是元素多，是**背景被看见的次数多**。

## 3. 材质

### 3.1 玻璃只有三种合法用法

**a. 窗框**——包住内容的外壳（弹窗、侧栏、控制栏）。面积越大，`saturate` 越低：
76px 的侧栏用 148% 没问题，1040px 的面板用 148% 会让整块玻璃被壁纸染色。

```css
/* 小面积：导航栏、控制栏 */
background: rgba(255, 255, 255, 0.68);
backdrop-filter: blur(21px) saturate(148%);

/* 大面积：页面级 */
background: rgba(255, 255, 255, 0.83);
backdrop-filter: blur(34px) saturate(80%);
```

**b. 悬浮物**——浮在页面上的临时元素（下拉、提示、浮层工具条）。可以玻璃，
但必须带明确投影，说明"我是临时浮起来的"。

**c. 内容区不再叠玻璃。** 要分层就用留白、发丝线、凹槽。给内容区再加一层半透明，
是最容易犯也最难自己发现的错——因为它"看起来有层次"。

### 3.2 页面是单窗 + 平铺

整页是一扇窗：标题、分类、主操作全部在窗框上，内容在窗内平铺。

```
┌─ 窗（玻璃，圆角 22，唯一一层投影）─────────────┐
│ 标题    分类 · 分类 · 分类        未保存  保存 │ ← 窗头
├────────────────────────────────────────────────┤
│ 分组                                            │
│ 标签   [____________]                           │
│ ───────────────────────────────────────────    │ ← 发丝线
│ 标签   [____________]                           │
└────────────────────────────────────────────────┘
```

反面是「玻璃侧栏 + 实白主面板」：页面被切成两块互不相干的表面，接缝处两种明度、
两种阴影、两种边界语法。用户说不出哪里不对，只觉得割裂。

三条附带规矩：

1. **窗口头属于窗口。** 标题和主操作与内容共享同一个容器边界。挂在外面的悬浮工具条
   会让"这个按钮控制谁"变成需要推断的问题。
2. **窗内只有一种边界：发丝线。** 1px、`rgba(19,26,45,.08)`。卡片框、内阴影、
   白描边一律不用。
3. **行的对齐就是页面的秩序。** 标签一列、控件一列，所有控件在同一条竖线上。

### 3.3 禁止清单

- 玻璃里套玻璃；内容区再叠一层半透明
- 在实白底上用白色描边（看不见）；在玻璃上用深色描边（会脏）
- 为了"层次感"把白底从 0.94 调到 0.92（屏幕上就是 1 个色阶，你只会因此再加一条描边）
- **给纸上的控件"打光"**：内白环 + 径向高光 + 本色外投影，三样凑齐色块就变成珠子。
  光只属于离地的东西；想表达"可改"，用虚线和措辞，不要用体积
- **直接露出原生控件外壳**：原生输入只负责行为，外观一律自绘
  （铺满自绘控件 + `opacity: 0`，点击照样唤起系统能力）
- 给小元素加 `saturate` 超过 120%（只会在浅色壁纸上留脏边）

### 3.4 复用控件前先问：它默认站在什么材质上？

小控件默认都照玻璃写：半透明白底、白色内高光、外投影。搬进实白的纸里三样全部失效，
投影方向还正好反了。

| 默认材质 | 搬到纸上要改什么                                            |
| -------- | ----------------------------------------------------------- |
| 玻璃     | 底 → 纯白（平放）或浅灰（凹槽）；白边 → 墨线；外投影 → 内阴影 |
| 纸       | 直接用，只复核墨线强度                                      |

不要改组件本身——它在玻璃工具条里还需要原来的样子。用容器作用域覆盖，
让组件保持"无立场"，由容器决定它站在什么材质上。

## 4. 刻度

**小于 1px 的调整不是设计，是噪音。** 它不会让人看到差异，只会让系统失去刻度，
而失去刻度之后下一个组件就只能凭手感，误差累积。

**字号：六档，只准选档，不准插值**

| 档位   | 值          | 用途                 |
| ------ | ----------- | -------------------- |
| 微     | 0.6875rem   | 尺寸、单位、辅助标注 |
| 正     | 0.8125rem   | 条目名、正文、按钮   |
| 中     | 1rem        | 需要一口气读完的短句 |
| 小标题 | 1.25rem     | 分区标题             |
| 标题   | 1.5rem      | 窗口标题             |
| 页标题 | 2rem        | 全页唯一             |

- 相邻档位至少差 1.22 倍，小于这个倍数看不出层级。
- 层级不只靠字号，还用字重：`400 / 560 / 640 / 680 / 760`。**不要用 500**。
- 大字负字距、紧行高（1.2）；小字正字距、松行高（1.5）。
- 数字一律 `font-variant-numeric: tabular-nums`，否则状态变化时宽度会跳。
- 密集容器整体降档，但不新增档位。

**圆角：同心递减**

外层减内边距等于内层；相邻两层差 4–8px，绝不差 1px。
单层元素从 `6 / 10 / 14 / 18 / 22` 里选，胶囊用 `999px`。

**间距：4 的倍数**

`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 56`。不出现 7px、9px、13px。

**时长：三档**

| 档位     | 时长  | 用于                         |
| -------- | ----- | ---------------------------- |
| 微反馈   | 120ms | 按下、hover、颜色变化        |
| 状态变化 | 200ms | 展开、切换、出现             |
| 布局位移 | 320ms | 面板进出、尺寸变化、共享元素 |

唯一例外：**确认反馈**可以到 520ms——它的作用不是"变化"，是"被记住"。

## 5. 边界与深度

> 浮在壁纸上的边界用**白**（轮廓光），落在纸上的边界用**墨**（深色细线）。

```css
/* 窗框：顶部轮廓光 + 描边环 + 三档离地，全在一条 shadow 里 */
box-shadow:
  0 1px 0 rgba(255, 255, 255, 0.78) inset,
  0 0 0 1px rgba(52, 42, 96, 0.06),
  0 42px 104px rgba(31, 25, 64, 0.28),
  0 12px 32px rgba(31, 25, 64, 0.12),
  0 2px 6px rgba(31, 25, 64, 0.06);

/* 纸上的卡片：墨画在纸上 */
border: 1px solid rgba(19, 26, 45, 0.09);
box-shadow: 0 1px 2px rgba(33, 27, 68, 0.035);
```

为什么分开：白描边的可见度取决于背景。同一根白线在浅色壁纸上消失，在深色处变成亮边，
**边界强度随背景波动**，这就是"看着不稳"。墨线不随壁纸变，因为纸永远是白的。

墨线深浅看**两侧明度差**：卡片里有内凹画布或深色内容时 `0.07` 够；纯白对纯白要 `0.09`，
否则边界退化成"一块飘着的白"。依据是差多亮，不是"想让它更明显"——后者会一路加到 0.15。

**深度必须成对出现。** 只有凸起、没有凹陷的界面像贴纸拼的。一个组件内部至少一次方向反转：

```
卡片（凸，外投影）
  └ 预览画布（凹，inset + 略深的底）
      └ 内容框（凸，小外投影）
```

凹的表达只有一种：`inset` 阴影 + 比容器略深的底。别用内描边假装。

**投影只有三档离地高度。**

| 高度 | 投影                         | 用于             |
| ---- | ---------------------------- | ---------------- |
| 贴地 | `0 1px 2px rgba(...,.04)`    | 纸上的卡片       |
| 微浮 | `0 12px 32px rgba(...,.12)`  | 下拉、提示、浮层 |
| 离地 | `0 42px 104px rgba(...,.28)` | 模态窗口         |

不要出现"离地 6px / 8px"这种中间值。高度只有三档，用户才读得出前后关系。

## 6. 视觉平衡

平衡不是"看着舒服"，是几件可以逐条检查的事。

### 6.1 对齐是秩序的来源

- **一个视图只给一条隐含竖线。** 标题、分组、内容、主按钮贴同一条左边距。多一条竖线
  就多一个"这块归谁"的问题。
- **两列表单：标签一列、控件一列。** 所有控件落在同一条竖线上；控件宽度设上限
  （约 440），不让它跟着窗口一起变宽——700px 宽的输入框会让标签和值失去关系。
- **同一行的不同高度元素按基线或中心对齐**，不按 top。在一行里混用三种对齐，比字号错一档更明显。

### 6.2 配重：一屏的重量要落得住

- 深色块、实色按钮、图片这类"重物"全挤在一角，其余是空的，画面就是歪的。
  用留白把重物推回视觉中心，或在**对角**补一点轻的重量（一行字、一条线）。
- 上重下轻比上轻下重稳。窗口头天然可以重，页脚不该比页头重。
- 配平靠**间距和对齐**，不靠加元素。加一个"平衡用"的装饰，下一个就得再加一个。

### 6.3 尺寸之间要有关系

- 圆角、间距、字号都从同一套刻度取；嵌套时同心递减。两个不同来源的 12px 不是同一个 12px。
- **容器变大，内容不要等比放大。** 控件有宽度上限，正文有行宽上限（中文 30–40 字）。
  1040px 的面板里铺满一行字，读者会丢行。
- **高度跟内容走，不为了拉平而生撑。** 硬把一列撑到和邻列一样高，会留下半张白页——
  那不是余量，是没画完。宁可压内容（并排字段、减一行），也不要撑容器。

### 6.4 焦点：一屏只有一个第一眼

- 第一眼应该是主操作或当前项，不该是装饰。
- 如果两三个元素在争第一眼，答案通常是：它们都不够重要。挑一个，降其余。
- 强调色一屏最多两处（见 §7）。超过两处，眼睛就没有落点。

### 6.5 灰阶自检

把截图转成灰度，颜色全部消失后：

- 前后关系依然成立 → 层级是靠深度和明度撑住的，合格。
- 只有加颜色才看得出层次 → 回去改投影、描边、留白，不要靠色相救。

这一条比任何参数都可靠，因为它检查的正是"你去掉颜色之后还剩什么"。

### 6.6 网格与像素

- 首页 16 列、80px 单元；卡片比格子**每边小 4px**（槽位留白）。
- 预览、缩略图按**真实卡片尺寸**算，不按格子尺寸算，否则底部会多出一条空玻璃。
- 对齐到整数像素。`transform: scale()` 之后可能出现半像素线，量一下再交付。

## 7. 强调色预算

**一屏最多两处。** 一处回答"我在哪"，一处回答"我能做什么"。其余全交给明度和字重。

- "已完成"不是第二个强调，是**撤掉颜色**。
- 一排并列的同类按钮不要每个都给强调色，那等于没有强调。
- 浅底上"淡描边 + 淡字"的按钮，在视觉上是"半个禁用"。
- 只从 `--theme` 派生，不手写色值；需要更暗用 `oklch(from var(--theme) calc(l * 0.78) c h)`，
  不要和深色直接混——混色掉饱和度，粉色会变发灰的品红。

**强度可以分档，语义不能分裂。** 判断标准是**它存在多久**：短期的可以重（模态里用实色块），
长期的必须轻（常驻侧栏用淡主题底 + 1px 细环）。反过来用，页面会永远处在"被抓着看"的状态。

**选中态：圈住整块，不要贴边色条。**

```css
.item {
  border: 1px solid transparent; /* 常驻占位，选中不挪动一像素 */
  border-radius: 10px;
}
.item.is-selected {
  border-color: color-mix(in srgb, var(--theme) 32%, transparent);
  background: color-mix(in srgb, var(--theme) 8%, transparent);
}
```

`inset 2px 0 0` 这类色条在这个项目里一定露馅：它不听圆角的话（两端被啃掉，头尾和腰
不一样粗）、只圈住一条边（用户看不出选中范围到哪结束）、而且是用阴影假装画线
（`inset` 只负责表达"凹进去"）。

四条配套：环用**真实边框**不用 `box-shadow`（会盖住相邻行、在浅底上就是一条脏边）；
底色 6%–10%（低了在玻璃上读不出，高了变成"被标红"）；环是唯一的"我在哪"，里面的图标
和文字不再各加一层强调；hover 是中性灰、选中是主题色，选中的行 hover 只把底色加深一档。

色条只在一种场合合法：**标线性坐标上的一点**——时间轴的当前时刻、进度、滚动位置。
判断问一句：这个标记是圈住一块，还是指出一点？

## 8. 信息只说一次

任何一条信息，在视觉层级里只能出现一次。

```
反面：标题"添加组件" + 副标题"选择后会直接放入首页网格" + 每行描述 + 按钮"可添加/已启用/可启用"
正面：标题"添加组件" + 每行"名称 + 4 × 2" + 按钮"添加/已添加/重新启用"
```

**删句测试**：删掉这句，用户会丢信息吗？不会 → 删；会，但下次操作就能看到 → 删；
会，且不会自己发现 → 留着，但降一个字号档。

**装饰必须承担功能。** 有一类东西既不是信息也不是装饰，是**假坐标**：
`01 / GENERAL`、`PLATFORMS / ACTIVE SOURCE`。问题不是不好看，是它们指向一个不存在的维度，
还占着一行、一种字重，和真正的标题抢注意力。自检：删掉它，界面丢了什么？
丢"我在哪"→ 留；什么都不丢 → 删；丢的是"这里有点东西"→ 这正是要删的，空白不是缺陷。

**不写旁白式 hint。** "改动即时生效""在网格里拖动可以换位置""悬停时暂停轮播"——
这些话对应的东西已经在界面上了，用户不会因为读了一句才学会。

按优先级替代：① 让控件自己说话（能拖的有手柄，能改的有凹槽），缺手柄就补手柄；
② 解释挂到悬停上（`title` + 问号图标，`tabindex` + `aria-label` 让键盘也读得到）；
③ 没有可调项就别留那一行解释。

例外只有一个：**用户不会自己发现、又影响信任或安全的事实**。压到最小字号，只说一次。

## 9. 动画

### 9.1 只有两条曲线

```css
--ease-out: cubic-bezier(0.22, 1, 0.36, 1); /* 进入、展开、位移 */
--ease-in: cubic-bezier(0.4, 0, 1, 1); /* 退出、收起 */
```

**进入慢停，退出快收。** 退出用 `ease-in` 且时长取进入的 0.65 倍，否则关窗会显得拖沓。
这两条是项目的事实标准，不要发明新的。

### 9.2 位移必须说明来源

- 从下方来 `translateY(12px) → 0`；从右方来 `translateX(12px) → 0`
- 原地成型的缩放是 `0.986 → 1`，不是 `0.9`。幅度大了感觉"页面在动"，
  小了才感觉"内容在成型"。

### 9.3 三条边界

- 不为了动而动：没有状态变化的元素不该有动画。
- 只动 `transform` 和 `opacity`，不让动效改变布局。
- 不超过 320ms（确认反馈除外），超过就是"慢"。

不做的动效：弹跳（贝塞尔带负值）、旋转超过 90 度、光芒/呼吸/闪烁（加载态除外）、
无限循环的装饰动画。

### 9.4 三件该做的事

**回响。** 点"添加"之后卡片闪一次（边框亮约 520ms 后回落）。这不是装饰，
是让用户确认"我点的是这个"。没有回响的按钮，用户会连点三次。

**阶梯。** 列表入场每项 22ms 递增，上限 10 项。人眼会读成"内容正在铺开"，
而不是"突然多了一堆"。

```css
animation-delay: calc(var(--i) * 22ms);
animation: rise 0.34s cubic-bezier(0.22, 1, 0.36, 1) backwards;
```

`backwards` 是关键，否则延迟期间元素会先显示再消失。

**跟随。** hover 把预览放大 2.5%，不要 10%。2.5% 是"它注意到了你"，
10% 是"它在抢注意力"。

### 9.5 必须降级

```css
@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.01ms;
    animation: none;
  }
}
```

不是可选项。用 `0.01ms` 而不是 `0`，某些浏览器在 `0` 时不触发 `transitionend`，
依赖它的逻辑会卡住。

## 附：新组件怎么推演

**归位 → 量尺寸 → 定层级 → 找一个强调点 → 想行为 → 过检查表。**

以"日程卡片"为例：它出现在首页网格里，是内容，属 L2，所以白底墨线贴地投影，不用玻璃；
4×2 即 4 个 80px 单元、圆角 14；卡片凸、内部时间轴凹；唯一强调点是"下一个事件"；
入场用 22ms 阶梯，hover 抬 2px 让投影从贴地升到微浮。
最后一步过检查表——如果"灰度截图"过不了，说明层级是靠颜色撑的，回去改投影和描边。
